# Slitherlink Game Design Document

## 1. Game Flow
Slitherlink is a logic puzzle where the player connects dots to form a single continuous loop.
- **Initialization**: A grid of dots is generated with clues (0-3).
- **Player Input**: Human player toggles edges between `ACTIVE`, `INACTIVE`, and `UNKNOWN`.
- **CPU Turn**: Invokes `HybridDPSolver` to complete the loop.
- **Validation**:
  - `validatePartial`: Checks local constraints (degree <= 2, clues not exceeded).
  - `validateFinal`: Checks global constraints (all clues met, single connected loop).

## 2. Solution Strategy: Hybrid DP + Backtracking
The solver uses a **Top-Down Memoized Row Bitmask DP** approach.

### Recursive Search (DFS)
- The solver explores the board's edge configurations using Depth-First Search.
- **State**: `dfs(row, vMask)`
  - `row`: The current node-row being processed.
  - `vMask`: A bitmask representing vertical edges entering the current row from above.

### Memoization
- A 2D array `visited[R+1][1 << (C+1)]` stores whether a particular `(row, vMask)` state has already been explored and failed to find a solution.
- This prevents redundant computation of subproblems.

### Backtracking
- Edge assignments are made directly on the `Board` for each row configuration (`hMask` and `vMask`).
- If a recursive call returns `false`, the edges are reset to `UNKNOWN` before trying the next configuration.

### Constraints
- **Node Degrees**: For each node, `v_in + h_left + h_right + v_out` must be 0 or 2. This allows dertmining `v_out` (the mask for the next row) from the inputs.
- **Cells**: For each cell, the sum of its four surrounding edges must match the clue.
- **Manual Placements**: The solver respects `ACTIVE` and `INACTIVE` edges placed by the player.

### Final Verification
- Upon reaching the end of the grid, `validator.validateFinal(board)` is called to ensure the single loop property.

## 3. Architecture (MVC)
- **Model**: `Board`, `Cell`, `Edge`, `Node`.
- **View**: `SlitherlinkApp` (Java Swing UI).
- **Controller**: `GameController` - bridges UI input with logic and the solver.
